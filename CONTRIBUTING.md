# Contributing

## Workflow

1. Create a short-lived branch from `main`.
2. Keep each change focused on one feature or fix.
3. Add or update tests for behavior that can regress.
4. Run the relevant checks locally.
5. Open a pull request with a clear description and verification notes.
6. Request review before merging.

## Branch names

Use a concise prefix and description, such as:

- `feature/card-sharing`
- `fix/private-note-access`
- `docs/setup-guide`

## Commit messages

Write commit messages as short commands, for example `Add card sharing endpoint`.

## Pull requests

Describe the user-visible behavior, the main implementation choice, and how the change was tested. Do not commit credentials, API keys, or personal contact data.
